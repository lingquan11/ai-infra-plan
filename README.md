# AI Infra 36 周学习计划

> 从 Linux 和 PyTorch 入门，一路做到算子、分布式训练、推理服务和集群平台。

[打开网页版](https://lingquan11.github.io/ai-infra-plan/)：可以勾选进度、写笔记，每个实践任务都能一键复制给 Muse，让它带你一步步做。

## 课程简介

36 周分 5 章（另有一个可选的 2 周）。每周四步：先读 AIInfraGuide 的中文文章建立直觉，再看课程补深度，然后在同一个模型上动手实践，周末用自测题检查。每章由讲义（`lecture/`）、动手实践（`lab/`）和成果展示（`showcase/`）三部分组成。

## 章节总览

| 章节 | 周次 | 主题 | 你将学到 | 你的收获 |
|---|---|---|---|---|
| [第 1 章 预备段](01-prep/) | 1–8 | Linux、PyTorch、Transformer 入门 | Linux 与远程开发、自动微分与 PyTorch、从 bigram 到 GPT、BPE tokenizer | 字符级 GPT、自己写的 BPE、第一批性能日志 |
| [第 2 章 训练主线](02-train/) | 9–21 | CS336 作业 1、2：一个模型从手写到分布式 | 从零实现并训练 Transformer LM，profiling 与 roofline，CUDA / Triton / FlashAttention-2，DDP、FSDP、张量并行与流水线并行 | 完整的 Transformer LM、自写 FlashAttention、手写 DDP、1 → N 卡扩展效率曲线 |
| [第 3 章 推理与服务](03-infer/) | 22–29 | 11-868 课件 + 给自己的模型写推理引擎 | KV cache 与 prefill / decode、continuous batching、PagedAttention、量化、投机解码、推理服务与压测 | 带 KV cache、continuous batching 和分页 KV cache 的推理引擎，压测报告 |
| [第 4 章 集群与平台](04-cluster/) | 30–34 | ZOMI AIInfra：通信、存储、调度、监控 | 集群网络与集合通信、checkpoint 存储、容器与 Kubernetes、GPU 调度、监控与故障恢复 | 运行在 K8s 上的推理服务、可调度的训练与推理、全链路平台 |
| [第 5 章 毕业项目](05-capstone/) | 35–36 | 技术报告 + 第一个开源 PR | 把性能日志整理成技术报告，选定方向并提交第一个开源 PR | 技术报告、第一个开源 PR |

## 学习路径

1. **[预备段](01-prep/)**（第 1–8 周）：Linux、PyTorch、Transformer 入门
   - 出口检查：第 8 周，见[第 1 章](./01-prep/)的「本章收获」
   - 过渡问题：这些优化你已经会用了，可它们内部是怎么工作的？主线会逐个拆开。
2. **[训练主线](02-train/)**（第 9–21 周）：CS336 作业 1、2：一个模型从手写到分布式
   - 过渡问题：为什么推理时 decode 阶段的瓶颈和训练完全不同？
3. **[推理与服务](03-infer/)**（第 22–29 周）：11-868 课件 + 给自己的模型写推理引擎
   - 过渡问题：训练任务和多个推理服务要共用一个集群时，资源该怎么分？
4. **[集群与平台](04-cluster/)**（第 30–34 周）：ZOMI AIInfra：通信、存储、调度、监控
5. **[毕业项目](05-capstone/)**（第 35–36 周）：技术报告 + 第一个开源 PR

## 如何开始

1. 打开[网页版](https://lingquan11.github.io/ai-infra-plan/)从第 1 周开始，或者在仓库里读[第 1 章](01-prep/)
2. 每周四步：读本章 `lecture/` 里的中文阅读 → 看课程 → 做 `lab/` 里的任务（可以在网页上点「复制给 Muse」让它带你做）→ 周末用自测题检查
3. 第 2 周建好主线仓库，之后的代码都放在那里
4. 每完成一周，把成果放进该章的 `showcase/`，然后运行 `python scripts/build_docs.py`

## 先修要求

- 一台能联网的电脑；Windows 用 WSL2 + Ubuntu（第 1 周会装好）
- 能读写基本的 Python
- 第 8 周开始需要按小时租用云 GPU，每周的硬件需求写在任务文件开头

## 维护

- 改路线只改 `plan.json`（网页也读它），然后运行 `python scripts/build_docs.py` 重新生成全部文档；CI 会运行 `--check`，忘了重新生成会报错
- 手写的只有各章 `showcase/` 下的成果目录和 `lecture/notes/` 里的笔记
